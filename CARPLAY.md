# Phase 7: CarPlay

AppDelegate creates and runs one headless-capable FlutterEngine, registers plugins on that engine once, and retains CarPlayManager. PhoneSceneDelegate subclasses FlutterSceneDelegate to forward scene lifecycle callbacks and attaches the phone's FlutterViewController to the existing engine. There is no scene storyboard or implicit phone engine. CarPlaySceneDelegate uses native templates and the same engine's cpdrive/car channel. It never creates a Flutter view or a second audio handler.

CarPlayManager initially shows a Loading row with the logo. Dart sends selected match folders from the same AudioHandler media tree as Android Auto. Tabs respect CPTabBarTemplate.maximumTabCount and list rows respect CPListTemplate.maximumItemCount, with an additional 20-match cap. Ordinary two-minute refreshes updateSections in place; changing tab order, visibility, language or authentication can replace the root. Match rows show title, score/status and the scaled logo. Empty/error/signed-out/hidden states use native rows. Selections call the existing handler and open CPNowPlayingTemplate.shared. audio_service remains the only owner of MPNowPlayingInfoCenter and MPRemoteCommandCenter.

Native refreshes and selections have deadlines and ignore stale connection callbacks. The bridge signals readiness and auth/settings/subscription changes. Disconnect releases timers and template references without stopping audio or destroying the engine. One phone scene can render Flutter; the other scene renders native CarPlay templates. Test that configuration on the chosen Flutter/Xcode versions because Flutter's support for multiple independently rendered scenes is limited.

## Configuration already saved

- Info.plist: UIApplicationSupportsMultipleScenes is true to permit phone and CarPlay scenes; UIWindowSceneSessionRoleApplication selects PhoneSceneDelegate with no scene storyboard; CPTemplateApplicationSceneSessionRoleApplication selects CPTemplateApplicationScene and CarPlaySceneDelegate. UIMainStoryboardFile is removed to avoid another engine. UILaunchStoryboardName still provides the launch screen. UIBackgroundModes/audio from Phase 5 supports ongoing audio. No additional photo, location or microphone permission is added for CarPlay.
- Runner.entitlements contains the audio entitlement inside the requested START/END XML comment. Its effective contents are an empty dictionary; unapproved device builds therefore do not request CarPlay.
- RunnerSimulator.entitlements enables com.apple.developer.carplay-audio. Runner Debug, Profile and Release use Runner/Runner.entitlements, overridden for iphonesimulator SDKs by Runner/RunnerSimulator.entitlements.
- The Xcode project includes PhoneSceneDelegate, CarPlaySceneDelegate and CarPlayManager in Runner Sources. AppDelegate is the existing entry point. The old SceneDelegate is removed. Device family remains iPhone and deployment target remains iOS 16.
- AppIcon contains car idiom entries for 60x60 points at 2x and 3x. The generated PNGs are 120x120 and 180x180 pixels. After regenerating normal launcher icons, run dart run tool/create_carplay_icons.dart to restore these entries and files.

## Build and test on a Mac

1. Copy the project to a Mac with current stable Flutter and an Xcode/SDK accepted by App Store Connect. Check [Apple's submission requirements](https://developer.apple.com/app-store/submitting/) at release time. Keep the app's iOS 16 deployment target; SDK version and deployment target are different settings.
2. In Terminal at the project root run flutter pub get, flutter gen-l10n, flutter analyze and flutter test. Create your local backend.json with real backend URLs using the README instructions. Do not add account passwords or tokens to that file.
3. Run flutter build ios --simulator --debug --dart-define-from-file=backend.json to generate Flutter build settings. If using the CocoaPods integration, run pod install from ios, then return to the root. Open ios/Runner.xcworkspace in Xcode, not the xcodeproj.
4. Select the Runner scheme and an iPhone Simulator. Runner target > Build Settings > All > Combined > search Code Signing Entitlements. Expand the setting and confirm simulator SDK values select Runner/RunnerSimulator.entitlements, while device values select Runner/Runner.entitlements. Do not enable the device entitlement before approval.
5. Runner target > Signing & Capabilities > Background Modes > enable Audio, AirPlay, and Picture in Picture if it is not already reflected by the saved plist. Verify the Runner bundle identifier and iPhone deployment settings. Product > Run.
6. In the iPhone Simulator, sign in to CP Drive and confirm phone playback. Simulator menu > I/O > External Displays > CarPlay. Open CP Drive on the car display. If the app is missing, check the built simulator entitlement, scene manifest, Runner Sources and simulator runtime compatibility; rebuild. This Windows session has not confirmed simulator discovery.
7. Exercise Live, Upcoming, Results and My Matches; logo, status text, empty/error rows, reordered tabs and Show in car off/on. Select both a TTS-backed and stream-backed live match. Verify Now Playing play/pause, next/previous and Stop operate the same phone player, without overlapping speech or duplicate remote controls.
8. Stay connected across multiple two-minute list refreshes and 25-second score refreshes. Confirm ordinary refreshes keep the list templates. Sign out on the phone while CarPlay is open: the car must show "Sign in to CP Drive on your phone when you are parked." Test network failure and API 401/403. There must be no gallery, web browser, video or login form in CarPlay.
9. Disconnect/reconnect the CarPlay display while phone playback continues. After a fresh process launch, connect CarPlay before opening the phone UI and confirm secure session restore and selection. Do not treat swiping the app away as ordinary backgrounding; iOS can prevent relaunch after a user force-quit.
10. After Apple approves the device entitlement, repeat on an iPhone and actual wired/wireless CarPlay system. Test after the first device unlock following boot, then with the phone locked; calls, navigation prompts, other audio, Bluetooth route changes, silent-loop gaps, Pause/Stop deactivation and reconnection. Simulator does not validate locked-device, Siri or real audio-routing behavior.

Sources: [Flutter shared-engine embedding](https://docs.flutter.dev/add-to-app/ios/add-flutter-screen), [Flutter scene lifecycle](https://docs.flutter.dev/release/breaking-changes/uiscenedelegate), [Apple simulator guide](https://developer.apple.com/documentation/carplay/using-the-carplay-simulator).

## Request and activate Apple's entitlement

1. Sign in at [CarPlay Contact Us](https://developer.apple.com/contact/carplay/) with the Apple Developer account that owns CP Drive. Choose Audio and describe sports commentary/broadcast playback. Submit the request text below with the requested account/app details. Accept the CarPlay Entitlement Addendum when presented and wait for Apple's approval email. Approval is not guaranteed.
2. After approval, Apple Developer > Account > Certificates, Identifiers & Profiles > Identifiers > select com.cricketerspitch.drive (or the actual replacement App ID) > Additional Capabilities > enable CarPlay Audio App (CarPlay framework) > Save.
3. Create new development and distribution provisioning profiles for the updated App ID. Download/install them. If automatic signing does not select an entitled profile, Xcode > Runner target > Signing & Capabilities > All > deselect Automatically manage signing > Provisioning Profile > Download Profile > select the correct CarPlay profile. Select the correct development team and signing certificate for each build configuration.
4. In Runner.entitlements remove the whole opening line containing "<!-- START CarPlay entitlement" and the closing line containing "END CarPlay entitlement -->". Keep the key and true value between them. Do not modify the simulator file. Recheck Code Signing Entitlements in all three configurations.
5. Build and run on an iPhone first. Verify the signed app and provisioning profile both include the audio entitlement, then test in the car. In Xcode choose the generic iOS device destination > Product > Archive > Organizer > Validate App > Distribute App > App Store Connect > Upload. Resolve signing/privacy validation failures before upload.
6. App Store Connect > My Apps > CP Drive > select the version > choose the uploaded build > App Review Information. Provide a working dedicated review account in the sign-in fields and paste the notes below. Complete privacy policy, privacy labels and other required metadata, then submit for review. CarPlay must be disclosed in the notes. Keep the review backend and match examples available during review.

[Apple entitlement and provisioning instructions](https://developer.apple.com/documentation/carplay/requesting-carplay-entitlements) explain the managed capability and additional review requirements. This workspace does not submit an entitlement request, change a developer account or publish an app.

## Ready-to-paste entitlement request

CP Drive (bundle identifier com.cricketerspitch.drive) is a Cricketers Pitch companion app providing cricket sports audio. We request the CarPlay Audio entitlement. Users browse Live, Upcoming, Results and My Matches using native CarPlay list templates, select a match, and listen to an available audio stream or spoken ball-by-ball commentary and score updates. Upcoming matches and results provide short spoken summaries. Now Playing supports play, pause, stop and next/previous match through the same media session used on the phone.

CarPlay contains audio browsing and Now Playing only. The phone app also includes a gallery and browser, which are not exposed in CarPlay. There is no video, web content, typing or login form in the car. Authentication is completed on the phone while parked; signed-out users receive a parked sign-in message. Lists are short and refresh every two minutes; active match metadata refreshes every 25 seconds. We will test interruptions, locked-phone use and reconnection on a physical CarPlay system before submission, and provide reviewer access to working match content.
